# Rich media investigation — 10 November 2026

The initial exploration found image, document, audio and video metadata that compact output then lost. One guarded background probe also read an existing video transcript without observed playback. The historical proposals and probes below are followed by implementation milestones. The current `read-media` command inspects exposed metadata, `read-transcript` reads guarded existing audio/video transcripts, and `save-media` prefers a verified exposed file-content Download route with an explicit rendition fallback or a source-verified static-image viewer fallback. `--original` requires that preferred route before any Download action. Download-route selection does not establish equality to the uploader's historical bytes; implementation and acceptance limits are recorded separately below.

Plan the work in three stages: preserve observed metadata and navigation references; establish an explicit, verified way to save originals; then expose existing descriptions and transcripts for understanding content. Keep each stage independently testable under the existing background interaction, activity-lock, pagination and output-format contracts.

## Proposed staged output contract

This is the historical design proposal, not the current JSON schema or command surface. See the implementation follow-ups and [current output contract](output-format.md#referenced-attachment-inspection) for supported commands.

- Media records: extend the existing `attachments[]` fields compatibly with observed label/filename, evidence-based `kind`, duration when exposed, description, separately named original/thumbnail/file-page/Download URLs, and observed transcript controls. A separate `media[]` surface would need an explicit compatibility decision. Preserve `contentRead: false` for metadata-only captures. Keep unknown MIME types and unavailable values explicitly unknown; an extension or preview icon alone does not establish a MIME type.
- `previews[]`: external link/unfurl records with source URL, observed title/description, preview kind and thumbnail where exposed. Keep these separate from uploaded attachments and do not promise original-file retrieval.
- Forwarded provenance: retain the enclosing message identity and separately observed source attribution. Do not silently replace either with the other or infer a source identity from the outer sender.
- Drill-down references: prefer an observed file ID; otherwise use a message-bound, validated media ordinal. Revalidate attachment identity and ordering on use, including after pagination. A raw AX node index or an ordinal without its message binding is not a durable reference.
- Proposed `read-media`: inspect one referenced attachment and expose only verified next actions. Proposed `read-transcript`: return an existing transcript with its selected-media binding and coverage. Proposed `save-media`: save a verified original to an explicit path. All three were unavailable at this exploration checkpoint.
- Default text: one concise attachment/preview line, useful description/duration and only implemented navigation hints. JSON retains structured evidence; full JSON preserves diagnostic receipts. Pagination must merge repeated attachment identities without collapsing distinct files or external previews.

## Observed Download saving implementation
