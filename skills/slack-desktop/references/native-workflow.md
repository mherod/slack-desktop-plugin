# Swift desktop implementation

The Bun wrapper compiles the explicit Swift source bundle in `scripts/slack-native-build.mjs` with `xcrun swiftc`, AppKit and ApplicationServices, ad-hoc signs it, and caches it under `~/.cache/slack-desktop`. The bundle includes `scripts/slack.swift`, `scripts/native/SlackAX.swift`, `scripts/native/SlackUI.swift`, `scripts/native/SlackInteraction.swift`, `scripts/native/SlackWorkspaces.swift` and `scripts/native/SlackViewerRecovery.swift`. No npm packages or Slack tokens are required. The wrapper captures native receipts, extracts semantic content through `scripts/slack-output.mjs`, selects and collects conversation/thread pages through `scripts/slack-pagination.mjs`, collects channel listings through `scripts/slack-channel-pages.mjs` and listings from the DMs view through `scripts/slack-dm-pages.mjs`, and renders concise text through `scripts/slack-format.mjs`. `scripts/slack-ui.mjs` validates and presents opt-in UI diagnostics and bounded after-error observations. `--format=json` returns full captured semantic records; explicit UI mode and error observations additionally retain their selected diagnostic nodes, without desktop samples. `--format=full-json` preserves the native receipt and exit status directly, even when extraction does not recognize a view. `read-media`, `read-transcript` and `save-media` additionally include wrapper resolution and retain failed reference/content verification in every format. Ordinary single-page reads have a 30-second process deadline; multi-page runs, two-capture media inspection and transcript reads have a 90-second deadline and compilation has a 60-second deadline. Saving uses the separate download/publication budgets described below.

## Native source layout

| File | Responsibility |
|---|---|
| `scripts/slack.mjs` | CLI lifecycle, activity lease, command routing and output handling. |
| `scripts/slack-search-query.mjs` | Public-search Unicode emoji translation and requested/submitted query receipts; no Slack input or runtime network access. |
| `scripts/slack-native-build.mjs` | Explicit source membership, captured build inputs, cache identity, snapshot compilation and signing for both native executables. |
| `scripts/slack.swift` | Signal setup, shared runtime state, source/destination verification, command flows and the marked CLI entrypoint. |
| `scripts/native/SlackAX.swift` | Shared errors, AX attributes, identity-aware traversal, geometry and structured capture with ancestry checks. |
| `scripts/native/SlackUI.swift` | Read-only diagnostic options, bounded capability inspection, redaction and after-error observations. |
| `scripts/native/SlackInteraction.swift` | Background/foreground mode parsing, foreground ownership, guarded AX/key input, final-window checks, desktop sampling and temporary clipboard preservation. |
| `scripts/native/SlackWorkspaces.swift` | Bounded workspace identity, selector discovery and explicit verified workspace transitions; ordinary workspace guards remain unchanged. |
| `scripts/native/SlackViewerRecovery.swift` | Privacy-safe image and file-details rejection evidence, complete repeated viewer-candidate verification and one-shot pre-Download cleanup coordination. |
| `scripts/slack-workspaces.mjs` | Independent workspace receipt validation and semantic extraction before every output format. |
| `scripts/slack-workspace-scope.mjs` | Binds a requested workspace transition to read sources, protocol phases and scoped semantic navigation hints. |
| `scripts/slack-save-file.swift` | Separate filesystem-only attachment publisher; it does not acquire Slack or accessibility capabilities. |

Source membership is explicit rather than discovered by directory globbing. The wrapper captures every required file after acquiring the activity lease, before checking the cache. The cache identity includes framed source names and bytes, the build recipe, architecture and OS release. Compilation consumes those same captured bytes from private temporary files; edits to any utility invalidate the bundle, and a missing source stops before a cached executable can be reused. The entrypoint is snapshotted as `main.swift`, as required by Swift's multi-file executable compilation. Utility files retain their own imports and compile into the same executable without widening access levels.

The shared builder preserves the existing compile/sign timeouts and cancellation callback. It publishes only a successfully compiled and signed binary by rename, and removes its own temporary build directory on success or failure. The publisher has its own source recipe, cache namespace and compiler options. Adding a native utility requires updating the explicit Slack bundle; it must not be added to the isolated publisher recipe.

The native guard harness uses the same captured source bundle and snapshot writer. It replaces only the uniquely marked `Command entry point` section with assertions, keeping the actual declaration and utility bytes. Missing or duplicate markers fail before compilation. This avoids finding an entrypoint by the last generic `do` block and keeps extraction tests on the production utility files. Signal setup and all shared state initializers remain in `slack.swift` in their original order. Extracted interaction helpers retain their existing guards and internal visibility; source-specific query, workspace, media and command verification stays in the command path.

An exclusive directory lock serializes cooperating invocations through native execution and formatting, including a requested native download and filesystem publication. `scripts/slack-lock.mjs` waits up to 30 seconds by default, or `--lock-timeout=0..120`, before reporting contention. Waiting is cancellable and starts no native helper. Owner metadata is bounded and excludes queries, targets and ownership tokens from diagnostics. A PID liveness sample does not prove owner identity or safe removal. Missing/legacy, malformed and unreadable metadata are explicit. Release verifies the acquired ownership before cleanup; changed ownership is preserved. No stale lock is stolen or removed automatically, and the lock does not serialize external UI tools or user activity.

The Swift process identifies one running `com.tinyspeck.slackmacgap` app with `NSRunningApplication`. It reads AX roles, titles, descriptions, values, children and URLs using `AXUIElementCopyAttributeValue`. Traversal is bounded by time, depth and node count; results describe the currently exposed accessibility tree only.

## Workspace discovery and switching

Workspace commands add `native/SlackWorkspaces.swift` to the explicit native bundle. `current-workspace` compares two current-client observations: canonical `https://app.slack.com/client/T…` or `/client/E…` URL, one workspace-wrapper name and native window identity. It does not open the selector or inspect message text. A `T…` team ID and `E…` enterprise context remain distinct.

`workspaces` opens or reuses the unique `p-account_switcher` popup under the current workspace's tab rail. The popup and menu items accept the observed optional `c-button--focus-visible` class while retaining their exact roles, base classes, enabled state and URL absence; other controls keep their existing shape checks. Its owned popover must directly contain the supported menu. Every workspace is a direct menu item with consistent checked class and AXValue, one direct name leaf, one direct domain leaf and matching row ordinals. Domains must be exact supported Slack domains, unique across the bounded inventory. Add-a-workspace remains excluded. No desktop/global keyboard shortcut, link opening, settings action or coordinate fallback is used. Listing may close only a selector it opened, through one window/PID-targeted Escape after re-verifying its exact menu, rows, window and unique owned selector focus; a pre-existing selector is preserved.

`switch-workspace` matches the exact observed `workspace:DOMAIN`, unique name, or current context ID. Inactive IDs are unknown and are never derived from domains. One verified AXPress targets the retained row after fresh identity, complete selector inventory, native-window and modal checks. The transition reacquires a ready client in the same native window, then opens its selector once to prove the selected name/domain is now the sole checked row and the prior row is inactive. Inventory identities must remain equal. A scoped Escape and a final stable client observation complete the switch. Focus must belong uniquely to the retained popup, menu or direct workspace row; permission, physical-input and deadline guards precede one key-down with guaranteed key-up. Already-current targets require unchanged state without a destination press. The existing `Workspace.root()` continues to reject every context/window change in ordinary reads and paging.

The shared activity lease spans discovery, input, verification and output. Native deadlines bound the transition, failed or uncertain input is never replayed, and every format retains workspace-switch uncertainty. Independent JavaScript validation requires consistent before/after identity, selector action evidence and destination proof before emitting success, including full JSON. Current-workspace and listing remain non-activating; only explicit `switch-workspace --interaction=foreground` may activate Slack through the existing foreground policy.

For `--workspace=REF`, the wrapper passes one prefix to the same native child as the requested read/search/listing or save command. The prefix is parsed before the existing interaction parser checks its unchanged command allowlist. One `workspaceCommand("switch-workspace", ...)` establishes the destination. Native code independently verifies its receipt, reacquires the same AX window with the exact observed context/name/URL, refuses an inherited open selector, and replaces only that command's pinned `Workspace`. The foreground controller is retained and the ordinary page budget starts after selection. No workspace restoration or second selection follows drift. Media keeps its two source captures; transcript selection/result remain in one interactive process.

Scoped emissions carry `requestedWorkspace`, raw `workspaceSelection`, conservative `workspaceSwitchMayHaveBeenRequested` and a fresh `workspaceScope` context/window stamp. Failure during final scope verification emits stopped diagnostics once. The wrapper validates this scope before accepting transcript tokens, remembering media bindings or rendering any format, checking every known client root and collection page against the selected context. Transcript panel-only captures remain subject to their existing source/panel checks and the fresh ambient scope stamp. Synthetic protocol failures may retain evidence in `preflight` or `nativeResult`; possible input cannot become false merely because a later receipt is malformed. Semantic `workspaceSelection` records selection separately from the requested operation, and supported follow-up hints retain the exact domain reference. Omitted scope preserves existing behavior. Scoped commands receive a separate 15-second wrapper allowance; their existing page counts and native collection limits stay unchanged.

**DO** use observed workspace references and retain unknown IDs. **Check:** wrong domains, duplicate/current markers, ambiguous names, changed menu ownership/window/inventory and forged transitions fail without substituting another target; no-op, failures and successful transitions remain distinct in all formats.

Scoped saving validates the selected workspace before initial attachment resolution, source reopening, viewer Download selection and the Download-started phase. The wrapper pins the complete native selection and process ID across phases, including the original window and before/after selection URLs; validating each phase independently is insufficient. Viewer-only content keeps its existing source/file checks and is accepted only under a verified save viewer phase with matching client context. Neither a filename nor a selected workspace supplies attachment identity.

After observing the exact native download completion, the scoped wrapper requests one `{verifyWorkspace: true}` checkpoint. The retained native helper calls its download monitor and emits phase `publish` with fresh workspace/window evidence; the wrapper checks that acknowledgment against the same Download selection and start time before starting the filesystem publisher. The direct route retains its source proof established before Download and fresh workspace/window plus playback checks; viewer/details routes also recheck their retained source. The checkpoint sends no Slack input, has no retry, and consumes the original completion deadline. Unscoped saving keeps its existing protocol. Final verification still follows publication, so a stopped command can retain a verified published artifact; text and JSON preserve that distinction along with source/viewer/Download and workspace-switch uncertainty.

## Explicit foreground fallback

The default remains background operation. `--interaction=foreground` requests one activation of the already running, uniquely identified Slack process through [AppKit's NSRunningApplication](https://developer.apple.com/documentation/appkit/nsrunningapplication). This uses the bundled Swift helper without AppleScript or an additional Automation permission. It supports listing, navigation, search, transcript reading and saving; pure inspection, media metadata inspection, permissions and help reject foreground mode.

The helper pins the workspace/window before activation, checks the original foreground process and physical input state, attempts activation at most once, observes Slack becoming frontmost and revalidates the pinned process/workspace/window before command input. An accepted activation request alone does not prove activation. Both modes use the same target-scoped AX actions, value writes and PID/window-targeted keys. Foreground mode adds an ownership check at input boundaries and desktop samples; an observed app switch stops the command and never requests activation again. Samples cannot establish continuous focus ownership or eliminate races with concurrent user activity.

There is no automatic background-to-foreground replay. A failed command may already have submitted Return, opened a viewer or started a Download. Inspect that state before deciding on a new invocation. Foreground activation never bypasses destination ambiguity, source identity, idle-player, pagination, clipboard or download checks. The shared activity lease spans activation and the existing command lifecycle. Completion/cancellation leaves focus where it is; no automatic restoration can steal focus back from the user.

Foreground receipts add `interaction` with the requested mode, activation attempt/observation and state. Semantic JSON retains this metadata without diagnostic PIDs; text adds one short foreground notice. Full JSON retains native evidence, including activation failures and protocol preflight evidence when final completion is missing. Unknown activation evidence stays unknown. Existing background output is unchanged, and emitted navigation hints do not inherit foreground permission.

**DO** treat foreground mode as per-command authorization to interrupt desktop use. **Check:** only its explicit flag reaches activation; the default stays non-activating, and a stopped search/save is never retried through a different transport.

## Effective AX access preflight

`AXIsProcessTrusted()` is a trust signal, not proof that Slack accepts AX messages. Before Electron initialization or foreground activation, the native helper sets a one-second per-message timeout on the pinned application and reads `AXRole` and `AXChildren` once each. The expected application role and a valid children array establish target access only; an empty array does not establish a workspace. The ordinary workspace, destination and source checks still follow. Failed reads retain their exact error code and operation rather than becoming an empty successful inspection or a guessed sign-in error. Apple documents [API-disabled errors separately from process trust](https://developer.apple.com/documentation/applicationservices/axerror/apidisabled).

`permissions` uses the same probe and separately reports trust and post-event access for the current helper invocation. `permissionScope: "current-execution-context"` identifies this boundary; the API flags do not reveal whether the process is sandboxed, whether host execution is approved, or why access is absent. False trust leaves the Slack probe `not-checked`, which is distinct from observing Slack return API-disabled. Its states are `ready` (all three verified, exit 0), `inspection-only` (trust and AX reads verified, no keyboard permission in this context, exit 0), `permission-required` (missing trust or API-disabled, exit 3), and `unavailable` (missing/ambiguous Slack process or other failed application reads, exit 1). `accessibilityProbe` retains the observed status, checked attributes, application child count when known, and exact AX error name/code/operation. Unknown target access never becomes ready. A normal failed command returns `status: stopped`, `accessStatus`, probe evidence and the same exit 3/1 distinction before input.

Before recommending OS setup, the caller verifies its execution mode and runs the same read-only `permissions` probe in the approved host context through the environment's normal tool permission mechanism. Existing authorization may cover that probe; a denied request remains blocked and cannot be retried through another transport. The helper cannot authorize or perform its own escalation. Only if trust remains missing or API-disabled persists in that approved context should explicit `permissions --request` request the normal OS prompt/open Accessibility settings, including API-disabled with a true trust flag. The helper never grants access, resets TCC approvals, restarts Slack or retries a command automatically. A later invocation performs a fresh probe; recovered access alone does not establish what caused the earlier failure. `inspect --ui` still captures bounded diagnostics on a failed probe, with any requested Electron initialization withheld. UI coverage adds up to sixteen sorted `axErrors` entries with code, name and count; these describe failed reads and remain separate from source identity or permission-grant evidence.

**DO** preserve failed AX evidence without weakening source verification. **Check:** trusted-but-disabled fixtures stop before activation, unavailable/timeout cases receive distinct remedies, and successful probes still pass through the existing workspace and attachment checks.

## Bounded UI diagnostics

`inspect --ui` enters a separate read-only capture path before navigation initialization. It reports advertised actions, attribute names, whether attributes are settable, known state and geometry using AX reads; it does not execute those capabilities. `--prepare` explicitly permits the existing bounded `AXManualAccessibility` initialization before capture. It neither grants OS permission nor enables a foreground, focus-setting or arbitrary-action fallback. Ordinary semantic `inspect` remains unchanged.

The filter is a literal case-insensitive substring over bounded role/subrole, ID, class and label fields, with at most 200 Unicode characters and no controls. Empty matches all. Depth defaults to 20 (0–40), and the returned-node limit defaults to 80 (1–500). Matching nodes retain their ancestors within the same cap. Capture-local indices remain in observed depth-first order; they are neither persistent element handles nor input selectors. Node metadata, capability arrays and text fields have explicit caps described in [the output contract](output-format.md#ui-inspection).

Each capture has an eight-second budget, at most 5,000 visited nodes and 12,000 AX read operations, plus a per-call IPC timeout. Required structural read failures prevent a claim that workspace selection completed. Unsupported/unavailable optional attributes stay null. The unique workspace root is preferred; absent, ambiguous or incomplete selection yields an application inventory with the limitation labeled. Start/end timestamps and root identities make the observation interval explicit. Boundary identity equality does not establish atomicity or unchanged contents, and no receipt proves the UI remains current after completion.

Composer/secure subtrees are cut before label/value/URL reads. Failed classification reads also cut content and descent, returning an `unreadable-content` structural stub. Structural aggregate content is omitted while retaining traversal; known view containers and lists read their own title/description without aggregate values. Capability names and settable checks remain observations only. Truncation, redaction, read errors and unknown booleans survive the validated JSON projection; full JSON retains the native result even when the diagnostic contract rejects it.

On a native failure, a read-only diagnostic attempt may capture the current view and useful controls under a separate two-second budget, 60-node cap and depth 30. It performs no accessibility preparation or input and does not retry the failed action. The original error/exit code and verified partial prefix remain authoritative. Text adds no more than six named controls and an inspection hint; JSON includes the bounded after-error observation. Its pinned workspace context describes intended scope when available, while the captured view describes what was observed afterward. Neither is a diagnosis of the failure's cause.

## Read-only media resolution

`read-media REF` uses the same activity lease, running-app discovery, bounded accessibility preparation and pinned workspace/window as other reads. It validates the attachment-reference shape before native app work. It adds no navigation, focus, keyboard, mouse, preview, playback, transcript or download action.

The native reader takes two independent structured captures. Each verifies the source view before/after capture, rejects a Search picker or modal, and retains an independently verified thread target when a thread is exposed. The semantic extractor reads all supported exposed main/search message rows and verified thread root/replies for resolution, rather than selecting an attachment from an arbitrary AX node or filename. Composer content remains excluded.

The wrapper requires both observations to agree on workspace and the requested attachment binding. A file reference resolves against observed current-workspace file identity. A message-bound ordinal also requires its recent remembered source/media-order digest; fresh captures alone cannot prove that `/m1` still means the attachment emitted by an earlier read. The private `~/.cache/slack-desktop/media-references.json` cache stores at most 1,000 recent message bindings for 24 hours within the same helper lease. Each record contains workspace ID, message reference, identity digest and observation time. Version 2 also retains attachment references with identity hashes, allowing `save-media` to locate a hidden file ID's remembered source; no message body, filename or URL is stored. Valid version-1 positional bindings remain readable, but cannot supply missing file-ID associations. The reader caps the cache at 512 KiB and rejects unsafe or malformed files; the writer evicts oldest records to remain within the byte bound. Writes replace a private mode-0600 file atomically inside the private cache directory. It is not a message archive or an alternate source of attachment metadata. Missing, invalid, expired or changed bindings require rereading the source rather than silently accepting the current ordinal.

Resolution returns one selected attachment's fresh metadata and supported source context. Repeated file observations retain their source/provenance information; conflicting identity metadata stops resolution; changing playback position or transcript-control availability is not treated as a file-identity change. The wrapper performs resolution for every format. Full JSON adds `resolution` to the native observations and preserves a failed verification as a stopped exit, so diagnostic mode cannot bypass identity checks. `--pages`, continuation flags and clipboard permission are unsupported for this single-attachment command; source pagination remains unchanged.

**DO** use current source evidence for media resolution. **Check:** the same reference resolves across both native observations and its required prior binding; otherwise output contains an actionable source-reread instruction, no selected media claim and no new input attempt.

## Saving an observed Download target

`save-media REF --output=PATH` retains the same activity lease and pinned workspace/window while a separate protocol coordinates source verification, one native Download action, selected download-state monitoring and local publication. `scripts/slack-save-media.mjs` validates selection and semantic output; `scripts/slack-save-runner.mjs` orchestrates the protocol and publisher; `scripts/slack-save-protocol.mjs` retains cancellation and incomplete-action evidence. The output path is wrapper-only. Its existing parent is canonicalized and pinned and its exact basename must be absent before Download selection and before publication. Relative user paths resolve from the invocation directory; the filesystem publisher receives an absolute path.

The native helper first emits two independent media observations and bounded candidates, retaining their actual AX identities in the same process. The wrapper resolves the requested attachment with the ordinary file-ID or remembered positional-binding checks. Direct selection requires a supported Download AXLink inside that exact media source, with an observed HTTPS `files.slack.com` `files-pri` or `files-tmb` URL carrying matching team/file identity. The wrapper supplies one offered selection token; malformed, unoffered or late input stops. Source navigation, viewer/menu opening, Download and owned-surface closure repeat window ownership and route-specific isolation immediately before input, after slower source reads. Viewer/menu opening and Download check their operation deadline after isolation, before marking the action attempted. Foreground mode permits only its initial activation; a lost foreground stops without reactivation or replay.

`classifyMediaExposure` separates verified absence from failed resolution. A potential matching attachment or ordinal source in either capture must pass the ordinary resolver. Only stable, complete canonical message/attachment inventories with neither the attachment nor any remembered source exposed can authorize reopening. The initial `select` response may contain one `{reopenSource: {workspace, messageRef}}` plan instead of a Download or viewer token. Older-message search is bounded and uses that conversation's own search control only when Slack's generated filter is securely bound to the destination. Unproven DM filter forms or ambiguous scope are not rewritten into a guessed conversation-ID/name query; they stop. After navigation, `source-select` carries two fresh observations and a new candidate inventory. Positional references still require the original ordered digest; file references still require the observed requested file identity. This phase cannot request another reopening. One native process retains the shared activity lease, pinned workspace/window and requested interaction guard across the transition; no fallback or retry follows attempted/uncertain viewer or Download input. Source navigation has its own bounded budget and does not add a public pagination option.

## Background pagination

Conversation and thread reads return logical pages of at most ten messages or replies. Initial channel/DM pages select the last ten loaded messages; initial thread pages select the first ten loaded replies and retain the root separately. The wrapper applies `slack-pagination.mjs` only after independent semantic extraction. It checks canonical timestamp order, uniqueness and agreement with the native capture before selecting a page. Text and compact JSON therefore expose the same page boundaries; full JSON keeps all current accessibility nodes for diagnosis.

`--before=CONVERSATION:TIMESTAMP` requests older messages and `--after=CONVERSATION:TIMESTAMP` requests newer messages. The flags are mutually exclusive and accepted only for `read-channel`, `read-dm` and `read-thread`. The wrapper rejects malformed references before invoking the helper. Continuation commands retain the positional destination: exact channel name, observed individual-DM display name, group reference or thread-root reference. A DM cursor's conversation ID disambiguates the current destination without invoking the picker again.

Before input, a continuation requires the pinned workspace/window, closed Query picker, matching current URL/title/kind or thread-root identity, and an exposed boundary timestamp in the identified message list. It does not navigate back to the target, close unrelated UI, or select the list that happens to own keyboard focus. Changing the view or losing the cursor produces a fresh-read instruction before scrolling. Channel/DM row selection excludes thread ancestry; thread selection uses only its independently verified list.

Eligible messages already loaded beyond the boundary are served without input. Otherwise, the helper chooses the oldest or newest verified edge row, rechecks the on-screen window, modal state and unchanged timestamp sequence, and requires the row to advertise `AXScrollToVisible`. It invokes that action once and reacquires the same destination for up to five seconds. The exact scrolled edge must remain exposed; overlap through a thread root alone cannot establish continuity. New eligible timestamps must settle across consecutive observations; final message identities are checked again after capture. The root itself never counts as an additional reply. No key, mouse, pointer movement, focus setter or activation is added by pagination.

Chromium's [accessibility action dispatcher](https://github.com/chromium/chromium/blob/156.0.8078.49/ui/accessibility/platform/browser_accessibility_cocoa.mm#L3032) exposes this action. Its [scroll-to-node implementation](https://github.com/chromium/chromium/blob/156.0.8078.49/ui/accessibility/platform/ax_platform_node_base.cc#L1673) can leave an already-visible target unchanged, which is why an accepted action without new message identities is reported as unknown progress rather than a history boundary.

The native receipt records `direction`, `cursor`, `status`, `beforeTimestamps`, `afterTimestamps` and `scrollAttempts`. Semantic output selects timestamps strictly before or after the cursor, excluding the boundary and keeping chronological order. Older pages take the nearest ten preceding records; newer pages take the first ten following records. Canonical timestamps, not reused DOM namespaces or message text, determine uniqueness. The next cursor comes from returned records, so a ten-message text cap cannot skip unread rows.

When the single scroll attempt exposes no additional eligible messages, the helper reports `no-progress` and withholds the same-direction continuation action. An accepted action or unchanged viewport is not proof of reaching a history boundary. `pagination.hasMore` remains null and `coverage.complete` remains false, including when observed thread-root/count evidence removes an unnecessary direction hint. The root section remains separate on every thread page, and may be null when outside the exposed view. Sidebar and search pagination use the separate workflows below.

## Version-specific input rationale

At Chromium 156.0.8078.49, Blink returns before screen-reader attribute serialization when extended properties are absent. `DefaultActionVerb` is among those later attributes; macOS advertises AXPress only when a default action exists and is not delegated to an ancestor. This explains how a readable tree can lack actionable Search/Home controls. See the pinned [serialization gate](https://github.com/chromium/chromium/blob/156.0.8078.49/third_party/blink/renderer/modules/accessibility/ax_object.cc#L1288), [default-action serialization](https://github.com/chromium/chromium/blob/156.0.8078.49/third_party/blink/renderer/modules/accessibility/ax_object.cc#L1994) and [macOS action advertisement](https://github.com/chromium/chromium/blob/156.0.8078.49/ui/accessibility/platform/browser_accessibility_cocoa.mm#L3045).

Electron 45.1.0 maps AXManualAccessibility to complete accessibility mode after a two-second debounce. Complete mode includes extended properties. Its getter compares the current mode exactly with complete mode, while its setter also adds screen-reader support; a false readback therefore cannot establish missing capability. The helper observes the target control's actions instead. See [Electron's attribute implementation and debounce](https://github.com/electron/electron/blob/v45.1.0/shell/browser/mac/electron_application.mm#L218) and [Chromium's complete-mode flags](https://github.com/chromium/chromium/blob/156.0.8078.49/ui/accessibility/ax_mode.h#L249).

Chromium's source at the installed version handles inactive first-click acceptance according to its configured mouse-acceptance policy. Later Chromium source adds an explicit exception for events posted by an external process; the associated Chromium issue describes dropped synthetic background clicks and the fix. This is evidence of version-dependent mouse handling, not proof that every inactive Slack click is discarded. The implemented workflow avoids relying on that mouse path. See the [installed Chromium source](https://raw.githubusercontent.com/chromium/chromium/156.0.8078.49/content/app_shim_remote_cocoa/render_widget_host_view_cocoa.mm), [current Chromium source](https://chromium.googlesource.com/chromium/src.git/+/HEAD/content/app_shim_remote_cocoa/render_widget_host_view_cocoa.mm), and [Chromium issue 566540085](https://issues.chromium.org/issues/566540085).
