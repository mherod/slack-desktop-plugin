# Troubleshooting

Symptom-by-symptom recovery for the slack-desktop helper. Inspect current Slack state before any retry, and never replay an action whose output says it may have occurred.

| Symptom | Remedy and continuation |
|---|---|
| Accessibility permission unavailable | The helper reports access in its current execution context, not a diagnosis of global macOS settings. Verify the invocation mode and run read-only `permissions` in the approved host context using existing authorization or the normal tool approval mechanism. If that request is denied, stop with the denial. If the approved-context probe still lacks access, explicitly run `permissions --request` for setup; the user enables the identity actually named by macOS. Recheck with `permissions` from that same approved context. Exit 3 means that invocation still lacks access. Before a new operation, inspect any earlier action uncertainty; never replay it automatically. |
| AX reads work but keyboard access is unavailable | `inspection-only` still permits read-only inspection. Verify post-event access with `permissions` in the approved context before suggesting keyboard-access setup for that host. If it remains unavailable, keep keyboard navigation stopped; foreground activation is not a remedy. |
| Trust is allowed but Slack returns AX API disabled | `accessibilityProbe.status` is `api-disabled`, with code `-25211`; it is not ready. First verify the approved execution context with the read-only probe through the normal tool permission mechanism. If API-disabled persists there, check the host/helper's Accessibility approval and Slack's current runtime state. Explicit `permissions --request` can open setup even when trust is true. Do not bypass a denied host request or the AX error through another transport or foreground activation, reset approvals automatically, or assume it is a sign-in problem. |
| Slack AX probe is unavailable, not running or ambiguous | Follow the specific probe remedy and inspect its error code. A timeout, malformed application response or multiple app processes does not establish missing permission. No Electron initialization, activation or command input follows a failed probe. |
| Empty or bounded-out AX tree despite an accessible probe | Inspect via documented Computer Use screenshot/AX tools if available. A failed AX access probe requires its own remedy first; do not use another transport to bypass it. Do not enable remote debugging, relaunch with flags or extract session tokens. |
| Search/Home/DMs exposes no AXPress | The helper requests full Electron accessibility once and waits for the control's capability. If it remains unavailable, input is withheld. Inspect the full receipt's recovery steps; do not retry unsupported AXPress or substitute shortcuts. |
| Search, Home/DMs tab or a sidebar row accepts AXPress but nothing opens | Current Slack builds can ignore AXPress. The helper falls back once to focus plus one guarded Return on the same verified control and records `ignored AXPress; activated it once with focus and one targeted Return` in `recovery`. If that stops with `Return withheld`, inspect which element holds focus; do not repeat the command blindly or press keys yourself. Other actions (thread reply pills, pagination, members, viewers, Send/Save/Delete) still use AXPress only. |
| `dms` stops with `DMs filter values are unavailable` | Slack's unread toggle can be a toggle button with an empty value, so the helper cannot verify whether the unread filter is on and stops before listing. Use `search` or `read-dm` (including `--allow-clipboard` direct DMs search) instead; the stop changes nothing. |
| Query or its selected suggestion does not uniquely own focus | Input is withheld. Inspect the overlay and resolve the focus state before retrying; the helper never sets focus or sends navigation keys to another control. |
| Exact suggestion cannot be selected | Return is withheld. Inspect the overlay before a deliberate foreground-mode command; activation cannot resolve missing or ambiguous identity. Autocomplete may append a preview to AXValue, so the exact selected suggestion and final result query are authoritative. |
| Normal individual-DM lookup has no exact match | With authorized temporary clipboard use, retry the same exact name or observed `@handle` with `--allow-clipboard`. The fallback requires complete direct-search candidate evidence and one exact person match; duplicate exact picker matches and arbitrary guard/navigation failures remain stopped. |
| Direct-DM fallback cannot verify a unique person or conversation ID | Use the inline observed-handle choices when offered, or inspect/directly search a more specific identity. Incomplete ARIA candidate coverage retains bounded candidate hints with `status: stopped`; group/fuzzy matches, missing timestamp identity and empty/loading message panes cannot authorize a read. If neither the exact sidebar control nor a different observed handle is available, inspect the selected but unverified view; no guessed ID, failed-query replay or repeated uncertain selection follows. |
| Ambiguous or unmatched individual-DM destination | Read the inline available candidates and follow the intended person's unique observed handle command. JSON retains up to twenty candidates when text's eight-row limit omits entries. A missing or non-unique handle gets no navigation command; inspect/refine the destination instead. Group names and fuzzy names are not selected automatically; follow a group reference from `dms`. |
| Group reference is no longer exposed in the sidebar | Run `read-dm group:CONVERSATION_ID` with the known reference. The helper reuses an exact loaded group or performs bounded exact-ID lookup. Missing, ambiguous, changed or expired lookup evidence stops; verify the reference/workspace and inspect the current state before another command. Do not replace the reference with guessed member names. |
| Need to find a DM beyond collected recent-list pages | Use `dms --search=TEXT --allow-clipboard` when temporary clipboard use is authorized, optionally with `--pages=N`. Read the labeled autocomplete matches and follow an offered handle or exact-group-name action. Directory people and option keys do not establish existing conversation IDs. |
| Clipboard opt-in missing or preservation/ownership guard stops | Nonempty search, group-name lookup and optional individual-DM fallback require `--allow-clipboard`; do not add it without authorization. Unavailable or oversized data stops before replacement. A detected newer copy is preserved and restoration status remains explicit. Inspect the stopped result before retrying; no automatic clipboard takeover follows. |
| Exact group-name search is ambiguous | Selection is withheld. Refine discovery or use a previously observed `group:CONVERSATION_ID`; do not choose the first same-name option or use its positional key as an ID. |
| Need to clear an existing DMs query | Run explicit `dms --search=`. It establishes a fresh DMs view and returns the ordinary recent-list capture without clipboard access, preserving workspace and unread state. Omitted `--search` and local `--filter=` do not clear Slack’s query. |
| Author is labeled `(inferred)` or not exposed | An inferred author comes from a structurally linked sender earlier in the same conversation capture; JSON identifies that source message. Missing grouping evidence or a boundary leaves the author null. Do not treat an inferred label as directly exposed metadata. |
| Thread message is not exposed | `read-thread` scrolls toward a message of the open conversation itself: up to 20 verified `AXScrollToVisible` steps within 25 seconds, on the oldest or newest exposed row, or on that row's own leading or trailing element when the row already fills the viewport. If the message belongs to another conversation, it first opens that conversation by exact ID and verifies it. The usual exact-message and reply-control checks follow. If the bound is reached or the conversation cannot be opened, locate the message with `search`, `read-channel` or `read-dm`, then follow its displayed `read-thread` reference. The helper does not treat a text search for a permalink as verified navigation. |
| Thread root text is outside the view | Read the verified replies and retained root link; JSON reports `root: null` when no collected page exposed the root. A multi-page collection retains an earlier exposed root once. A requested reply must itself be exposed initially, and missing/loading replies are not reported as an empty thread. |
| Starting a DM read from Search or the DMs hub | The helper exposes Home before selecting the person, so the resulting conversation has a verifiable URL. An existing picker over a canonical conversation can be reused directly. |
| Message list missing, has no loaded rows, or changed during capture | The command waits for loaded rows in the matching main conversation list, then stops if readiness remains unknown. An empty conversation and a still-loading view are not reported as a successful zero-message read. Inspect before another operation. |
| Need older channel/DM messages or more thread replies | Follow the exact `Older`, `Newer` or `More replies` command, optionally adding `--pages=N` (1–10). Each page consumes eligible loaded messages first, then can scroll the identified message list once. |
| Need more sidebar channels | Use `channels --pages=N` (1–10) to collect downward from the current sidebar position. Text stays capped at 30 channels total; JSON retains all collected channels. This does not open channels, expand sections, change filters or enumerate the entire workspace directory. |
| Need DM conversations beyond Home’s sidebar | Use `dms`, optionally with `--pages=N` (1–10), to collect from the DMs view at its current position and filter state. One-to-one, group and self rows are listed without opening conversations; text caps the collection at 30 rows and JSON retains all collected records. Semantic listing records omit message previews and do not establish DM history or complete group membership. |
| Recent-list DM has no read action | Individual duplicate names across observed IDs, unsafe names and names beginning with `@`, `group:` or `group-name:` receive no name hint. Group hints use the observed conversation ID. Do not invent a handle. An offered exact-name hint is scoped to the observed listing, so `read-dm` still verifies its picker and can stop on ambiguity. |
| A listing stops with no progress or scope changes | A DM-only sidebar capture can advance `channels`; unsupported canonical rows can advance the DMs view list without becoming returned records. `no-progress` means the bounded attempt exposed no new rows, not that no more conversations exist. If the DMs filter, unread toggle, row order or identity changes, retain the verified prefix and inspect the view before another command. Do not automatically repeat the same scroll. |
| A local DMs filter returns zero matches | Read the observed and matched counts, completed pages, and Slack query/unread labels. Zero matches covers only the verified collected records, not all conversations or full group membership. Increase `--pages` within its bound to inspect more exposed rows, or use `--filter=` for no local restriction; Slack’s existing search text remains unchanged. A missing/loading or unsupported list still stops instead of proving an empty directory. |
| DMs view is missing, empty/loading, or exposes only unsupported rows | The helper stops instead of reporting a complete or verified empty directory. Inspect the current DMs view and its filters before another command; do not clear filters, toggle unread mode or select a conversation as an automatic recovery. |
| Need more search results | Use `search QUERY --pages=N` (1–10) to collect consecutive result pages in one command. Text labels omitted matches; JSON retains all collected matches. Search has no `--before`/`--after` cursor. |
| A quoted search stops in the picker | Preserve the literal quotes in one shell argument. The helper verifies Slack's observed HTML-encoded query label against the exact requested text and literal Query value; it never strips quotes or decodes entities to make a match. Unknown transformations or multiple query options still stop before Return. Inspect the current picker before a fresh request. |
| An emoji search cannot be translated | Read the unsupported sequence or filter-context error. The wrapper stops before native input rather than mapping part of a joined emoji or guessing a name. Use an explicit known Slack shortcode when appropriate; inspect any earlier uncertain navigation before another request. |
| Search page control is unavailable or query/filter/sort/page evidence changes | The helper stops before further input or after the single attempted press; it does not guess another control or repeat the press. Retain any verified prefix, inspect the current search state, then decide on a fresh query. Hidden filter values remain outside verification. |
| Page cursor or destination changed | Read the intended destination again for fresh references. Continuations require the same view and an exposed boundary message; they do not reopen a conversation or guess a scroll target. |
| Pagination reports `no-progress` | No additional messages were verified after the bounded attempt. Stop that direction or use an offered opposite-direction action; do not infer that all history was read or loop the same cursor. |
| Multi-page read stops early with `status: partial` | Exit 1 retains previously verified pages with the error and no pagination hints. Inspect current state before a fresh read; do not automatically replay input or assume the requested page budget was collected. A 60-second native collection budget stops before another page; the wrapper's 90-second process deadline remains a final bound. |
| Default text shortens a message | Use `--format=json` for full captured text on the same selected pages. Use continuation commands or `--pages=N` for additional messages, and `--format=full-json` when the accessibility tree or desktop samples are needed. |
| Media text is shortened or attachment/preview records are omitted | Use `--format=json` for every captured media record on the selected message pages. A shorter text view does not remove records from JSON or fetch more media. |
| `read-media` reports an absent, stale or changed reference | Keep the source message exposed and reread it with `read-channel`, `read-dm`, `read-thread` or `search`, then follow its fresh attachment hint. The helper verifies current metadata; it does not navigate to a hidden file or treat `/pN` previews as attachments. |
| Transcript is generation-only, unavailable, or cannot be bound to the selected media | Reread the source and follow a fresh existing-transcript hint when offered. The helper does not generate a transcript or use playback to produce one. Inspect a changed or unsupported panel before another command; no uncertain press is replayed. |
| Transcript text is shortened or more segments are needed | Use `--format=json` for every collected segment and add `--pages=N` (1–10) for additional downward captures. Already exposed segments may cover more than the viewport. No progress does not prove completeness; do not loop the same scroll. A later failure returns only the verified prefix with exit 1; inspect before a fresh read. |
| A Download URL does not establish an original | `save-media` prefers the verified file-content Download route and reports its selection; that route still does not establish equality to the uploader's historical bytes. Use `--original` to refuse a rendition fallback. Preserve unknown byte identity/MIME type; do not rewrite the URL or infer content from the extension. |
| `--original` has no unique verified file-download route | Reread the source or inspect exposed metadata. Stop before Download; do not guess a URL or automatically remove the requirement. The default command may use a unique observed fallback only when that meets the requested save. |
| `save-media` cannot find an unexposed source | Use a recent reference from a successful message read/search in this workspace. Hidden file IDs need a remembered file-to-message association; positional refs need their original order binding. An individual DM without an exact observed navigation route, an unsupported generated search scope, missing/expired/conflicting evidence or a source outside the bounded lookup stops without Download. Refresh the source manually through the read/search commands before a new request. |
| Source reopening stopped or its result is uncertain | Inspect `sourceMayHaveReopened`, `source.opened`, `source.messageRef` and `downloadMayHaveStarted` separately. Slack may now show another conversation or search; inspect that state before a new command. The helper does not replay uncertain navigation or reopen a changed exposed source. |
| No Download control belongs to the attachment | A supported static-image gallery can verify its viewer's active image and scoped Download button. A document/file, audio or video source with a supported exact `View file details` button, or inline video with its verified `More actions` → `View details` route, can verify its retained source, active same-file card and observed Download URL. Both paths require a known file identity. Other controls or layouts stop with a source-reread hint; no URL is guessed. Unsupported, disabled or ambiguous source Download controls do not permit either fallback. |
| The viewer may have opened but Download was withheld | Inspect `viewerMayHaveOpened`, `viewer.opened`, `viewer.closed` and `downloadMayHaveStarted` separately. Image and file-details capture refusals retain `viewer.failure` from the rejecting capture and `viewer.cleanup` from the later cleanup attempt. Cleanup closes only this operation's retained viewer or pane after fresh exact source/file checks and, for audio/video, verified idle playback. A mismatch, replaced panel, incomplete capture, expired input budget or uncertain action withholds Close. Successful cleanup leaves the save stopped. An unresolved video menu is not dismissed or replayed. Inspect uncertain closure before another request. |
| Slack's native download directory is not configured, or a save dialog appears | Stop and report the prerequisite or observed dialog. The helper does not change preferences, enter dialog paths or repeat the Download action. |
| The output already exists or its parent is missing/changed | Choose an unused exact file path under an existing parent. Existing files, directories and symlinks are preserved, including destinations created during the copy. |
| Download completion times out, is cancelled, or loses its interaction guard | Slack may still complete the native download. Inspect Slack Downloads and the reported output path before another request; the helper does not replay the action or delete the native file. |
| Quarantine is absent after native completion | The publisher waits up to ten seconds for Slack's quarantine attribute, then stops without publishing if it remains absent. The native copy is retained; no unquarantined fallback is used. |
| Output reports published but unverified, or publication uncertain | Retain the reported artifact path and failure receipt. Inspect the destination before retrying; a stopped exit is not evidence that no file was created. The helper never overwrites or removes that artifact. |
| Search cannot open or channel absent | Inspect the workspace/search scope and recovery steps. An accepted input without the expected after-state is still unresolved. |
| Native dialog, sheet or menu blocks navigation | Dismiss the blocking UI before retrying. The helper does not send arbitrary Escape, accept a confirmation or discard a draft. |
| `members` stopped with its channel-details dialog still open | Inspect the current view, then use `close-members` to close only the verified current channel's Members dialog. Member-name parsing is not required. Unknown tabs, foreign dialogs or changed channel identity remain stopped. Inspect close uncertainty before any further input. |
| Hidden/minimized window or ambiguous workspace | Navigation requires one identifiable on-screen workspace window. An exposed sidebar or already-open exact channel/group DM may be read without that match, but unavailable AX content still stops the read. Do not activate, unminimize or guess a window. |
| Another helper holds the activity lock | The wrapper waits up to 30 seconds, or the explicit `--lock-timeout=0..120` budget, before returning owner diagnostics. Wait for the owner to finish; neither a missing owner file nor a non-running PID authorizes automatic lock removal. Resolve a stale lock only after independently verifying ownership and termination. |
| Compilation/cache access blocked | Report the exact compiler/permission failure and use the environment's normal permission mechanism. Do not bypass a denied resource. |
| UI changed during an operation | Retain any verified prefix and read the bounded after-error observation. Use `inspect --ui --filter=Query` for picker evidence or `inspect --ui --filter=c-virtual_list --depth=30` for list structure. Inspect again before deciding on input; never repeat an uncertain Return automatically. |
| Diagnostic capture exposes only an application root or reaches its limits | Read root selection and coverage reasons. Refine the filter or increase depth/limit within their bounds. If runtime AX initialization is needed, explicitly use `inspect --ui --prepare`; permission failures require the approved-context check above before OS setup. A zero-result or limited capture does not prove the control is absent. |
| Accessibility references repeat or message ancestry conflicts | The helper skips repeated native identities and retains distinct elements even when labels match. Inspect `coverage.repeatedReferences` and `coverage.rootRepeatedReferences` in UI diagnostics. A structured-ancestry conflict or genuinely exceeded bound still stops; obtain a fresh verified view before retrying. Do not foreground or restart Slack to force recovery. |

Workspace target missing or ambiguous: run `workspaces`, then use an exact emitted `workspace:DOMAIN` reference. Inactive context IDs are not inferred. Add/Join/sign-out controls are never switch targets. If switching stops after possible input, read `current-workspace` and inspect the selector state before another request. Preserve `workspaceSwitchMayHaveBeenRequested`; no uncertain switch or selector action is automatically repeated.

Scoped read stopped: distinguish `workspaceSelection` from the requested operation. A verified workspace switch does not establish a successful read. Keep its switch uncertainty, the original read error and any verified partial coverage; use `current-workspace` to inspect state before another command. No requested read/search/list action follows missing or ambiguous workspace selection.
